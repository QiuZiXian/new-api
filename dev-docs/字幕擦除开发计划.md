Plan: 字幕擦除渠道 (CII Subtitle Erase)

 Context

 平台已集成 CII 仓山区公共服务平台的内容生成能力（doubao / Seedance 视频生成任务），但尚未覆盖 字幕擦除 这一独立的视频处理能力。CII 字幕擦除 API 是一个异步任务：

 - 创建：POST /api/v1/videos/subtitle-erase/tasks，请求体 {"video_url": "..."}，返回 {"success": true, "task_id": "se-..."}。
 - 轮询：GET /api/v1/videos/subtitle-erase/tasks/{task_id}，返回 {"status": "running|completed|failed", "result": {"video_url": "..."}, "error": {...}, "created_at": ..., "finished_at": ..., "expires_at": ...}。
 - 计费：第三方视频 1 积分/秒（不足 1 秒按 1 秒），平台生成视频免费；上游不在响应里直接标注是否免费。

 用户确认的关键约束：不与现有视频生成路由共用（不复用 /v1/video/generations 也不复用 /v1/videos/{task_id}），而是新增两条独立路由：

 - POST /v1/videos/subtitle-erase/tasks — 创建擦除任务
 - GET /v1/videos/subtitle-erase/tasks/{task_id} — 查询擦除任务（按 task_id 走平台本地 model.Task 表，必要时再触发实时拉取）

 用户已确认的设计决策

 1. 渠道名：CiiSubtitleErase（常量 ChannelTypeCiiSubtitleErase = 61，包名 ciisubtitleerase，UI 名称 CiiSubtitleErase）。
 2. 计费：Pre-charge 0，结算时按 finished_at - created_at 实际秒数 × 1 积分；异常值（< 0 或 > MaxTaskDurationSeconds × 4）直接判定为异常并返回错误。
 3. video_url 入口：通过 metadata.video_url 传递（不改 TaskSubmitReq DTO）。
 4. 列表/取消端点：不实现（仅保留 POST 创建 + GET 单任务查询）。

 2. 新增任务适配器包

 新建 relay/channel/task/ciisubtitleerase/

 两个文件：

 package ciisubtitleerase

 - adaptor.go：实现 channel.TaskAdaptor 接口（参考 relay/channel/task/doubao/adaptor.go:109-530），重点差异如下。

 - 结构体

 type TaskAdaptor struct {
     taskcommon.BaseBilling  // 嵌入 no-op 钩子
     ChannelType int
     apiKey      string
     baseURL     string
 }

 - 请求体转换（BuildRequestBody）：从 req.Metadata 读 video_url，序列化为 {"video_url": "..."} 发往 POST /api/v1/videos/subtitle-erase/tasks。video_url 缺失或空字符串时直接报错（400）。

 - 响应解析（DoResponse）：解析 CII 提交响应 {"success": true, "task_id": "se-..."}，取 task_id 作为上游任务 ID；构造 dto.NewOpenAIVideo() 返回给客户端。success=false 或缺 task_id 时包成 TaskError 返回（参考 doubao 对空 id 的处理逻辑 adaptor.go:267-279）。

 - 轮询（FetchTask）：GET {baseURL + path}/{taskID}，Authorization Bearer。

 - 结果解析（ParseTaskResult）：映射上游状态字符串：
   - "running" → model.TaskStatusInProgress，进度 "50%"
   - "completed" → model.TaskStatusSuccess，进度 "100%"，Url = result.video_url
   - "failed" → model.TaskStatusFailure，进度 "100%"，Reason = error.message
   - 默认（异常上游状态）→ model.TaskStatusInProgress，进度 "30%"
   - 重要：CII 的 success: true 是 API 调用层结果，与任务最终状态无关——必须以 status 字段为准。

 API path 处理：复用 doubao 的 normalizeTaskApiPath 写法（防止 path injection），从 info.ChannelOtherSettings.TaskApiPath 读，缺省回退 defaultSubtitleEraseApiPath。

 OpenAI 视频响应（ConvertToOpenAIVideo，实现 OpenAIVideoConverter）：把 task.Data（即 CII 轮询响应原始字节）翻成 OpenAIVideo；状态用 task.Status.ToVideoStatus()，metadata.url 填 result.video_url，错误时填 error.code / error.message。

 不实现 DeleteTask（CII 没有对应的删除端点；doubao 自己的 DeleteTask 也不在 TaskAdaptor 接口中，是可选扩展）。

 计费钩子（重点）：

   - EstimateBilling：直接返回 nil（不预扣）。
   - AdjustBillingOnSubmit：返回 nil。
   - AdjustBillingOnComplete(task, taskResult)：在 task 终态时被轮询循环调用。逻辑：
       i. 解析 task.Data 取 created_at 与 finished_at。
     ii. 计算 actualSeconds = finished_at - created_at。
     iii. 异常判定：
           - < 0 → 写 task.FailReason = "subtitle erase duration invalid: negative"，返回 0；让轮询循环走失败分支。
       - > 4 * relaycommon.MaxTaskDurationSeconds（即 > 14400 秒 / 4 小时，远超 CII 文档"2-3 小时"上限）→ 写 task.FailReason = "subtitle erase duration invalid: exceeded 14400s"，返回 0。
     iv. 合法范围（0 < actualSeconds ≤ 14400）：返回 common.QuotaFromFloat(float64(actualSeconds) * quotaPerSecond)（quota 换算系数沿用 common/quota_math.go）。actualSeconds == 0：返回 0。
   - 异常路径用 common.SysError + logger.LogWarn 输出 task ID 与异常详情便于排查。

 关键不变量：必须使用 common.QuotaFromFloat / common.QuotaFromFloatChecked 完成 quota 转换；不要在 adaptor 里写 int(float64 * ratio) 裸转换（参考 AGENTS.md "Billing safety invariants"）。

 5. 新增独立路由

 router/video-router.go

 在 SetVideoRouter 内追加独立的路由组（参考现有 Kling / content tasks 的写法，但绑到我们自己的 path）：

 // 字幕擦除（独立路由，不与视频生成共享）
 subtitleEraseV1Router := router.Group("/v1/videos/subtitle-erase/tasks")
 subtitleEraseV1Router.Use(middleware.RouteTag("relay"))
 subtitleEraseV1Router.Use(middleware.TokenAuth(), middleware.Distribute())
 {
     subtitleEraseV1Router.POST("", controller.RelayTask)
     subtitleEraseV1Router.GET("/:task_id", controller.RelayTaskFetch)
 }

 要点：

 - TokenAuth + Distribute 中间件照搬 videoV1Router（router/video-router.go:19-32）的链，确保 Distribute 按 model 字段把请求分到 cii-subtitle-erase 这个模型对应的渠道（管理员只需建一条 ChannelTypeCiiSubtitleErase 渠道并启用 cii-subtitle-erase 模型）。
 - 复用 controller.RelayTask 与 controller.RelayTaskFetch（controller/relay.go:477, 492）作为处理函数——它们已经是平台任务的统一入口，会走到 relay.RelayTaskSubmit / relay.RelayTaskFetch，进而命中 GetTaskAdaptor(platform) 路由到新适配器。
 - controller/relay.go:388 的 isOpenAIVideoAPI := strings.HasPrefix(c.Request.RequestURI, "/v1/videos/") 已经能识别本路径，会走 OpenAIVideoConverter.ConvertToOpenAIVideo 分支——新适配器实现了这个接口。

 6. 模型名分发

 由于 CII 上游 POST 请求体里没有 model 字段，客户端发的 model 字段只是平台层面的路由键。relay/common/relay_info.go 的 GetTaskRequest 已经会反序列化 metadata，我们的 BuildRequestBody 直接从 req.Metadata["video_url"] 取值。

 不需要新增 DTO 字段。客户端请求示例：

 {
   "model": "cii-subtitle-erase",
   "prompt": "remove subtitles",
   "metadata": {"video_url": "https://example.com/source.mp4"}
 }

 relay/relay_task.go 的提交控制器不会拦截额外的字段，让 metadata 原样落到 req.Metadata 即可。

 7. 异常处理与平台规范一致性

 Out of Scope

 - 列表/取消端点（GET /v1/videos/subtitle-erase/tasks 列表、DELETE）。
 - 同步 Adaptor（字幕擦除本身无同步形态）。
 - streamSupportedChannels（无流式响应）。
 - 自动判断"平台生成视频免费"——CII 上游没在响应里直接告诉，平台侧目前不区分，全部按 1 积分/秒计费（与 CII 第三方视频一致）；后续若 CII 在响应里增加 is_platform_video 字段，可扩展 AdjustBillingOnComplete 跳过计费。
