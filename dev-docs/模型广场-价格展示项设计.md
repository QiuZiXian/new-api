# 模型广场 · 价格展示项（PriceItem）设计

> 目标：让模型广场详情页的 4 种排版（大语言模型 / 文生图 / OCR / 视频多档）
> 都能渲染，同时**不改任何计量计费底层逻辑**。
>
> 配套评估：`模型广场-计费与配置对齐评估.md`

## 1. 核心原则：展示项只描述「怎么展示」，不存价格

价格数值**永远**由既有计量配置实时推导。管理员改 `model_ratio` / `model_price`，
模型广场上的价立刻跟着变——这才是「计量配置 + 模型额外配置 = 展示信息」的真对齐，
不会出现两处配置漂移。

```
计量计价设置（system-settings/billing）      models 表（metadata）
  ModelRatio / CompletionRatio / CacheRatio        price_items（展示项 JSON）
  ModelPrice / AudioRatio ...                      context_length / category / capabilities
              │                                              │
              └──────────► updatePricing() ◄─────────────────┘
                                 │
                                 ▼
                     /api/pricing → price_items[]
                                 │
                                 ▼
                     PriceItemTable（四种排版通用）
```

## 2. 数据模型

### 2.1 models 表新增列（`model/model_meta.go`）

| 列 | 类型 | 说明 |
|---|---|---|
| `context_length` | int | 上下文长度 |
| `max_output_tokens` | int | 最大输出 |
| `category` | varchar(64) | 分类 |
| `capabilities` | varchar(255) | 能力，逗号分隔 |
| `input_modalities` / `output_modalities` | varchar(128) | 输入/输出模态，逗号分隔 |
| `price_items` | text | 展示项 JSON 数组 |

全部走 AutoMigrate 加列，不动既有列、不动计费字段。

### 2.2 展示项配置（`models.price_items`）

```json
[
  {
    "id": "seedance-2.0-video.fast.480p",   // 计费标识，纯展示文案
    "group_key": "video_output",            // 语义键，前端走 i18n
    "group_label": "",                      // 自定义分组文案，优先于 group_key
    "variant": "Fast快速 · 480p",            // 「维度」列
    "billing_ref": "video_output_second",   // 计量绑定，决定价格从哪推导
    "unit": "second",                       // tokens / image / second / request
    "origin_price": 2.0,                    // 可选，>现价 时自动算折扣
    "enabled": true
  }
]
```

同一 `group_key` 多行 = 视频多档排版（功能列纵向合并，维度列分档）。

### 2.3 下发行（`Pricing.price_items`）

```json
{
  "id": "seedance-2.0-video.fast.480p",
  "group_key": "video_output",
  "variant": "Fast快速 · 480p",
  "unit": "second",
  "price": 0.35,
  "origin_price": 2.0,
  "discount_label": "1.8折",     // 后端自动算
  "saved_percent": "82.5%"       // 后端自动算
}
```

## 3. 价格推导规则（`model/pricing_item.go`）

统一换算口径（与前端 `lib/price.ts` 一致）：**1 倍率 = $2 / 1M tokens**。

| billing_ref | 推导 | 依赖配置 |
|---|---|---|
| `input_tokens` | `ratio × 2` | ModelRatio |
| `output_tokens` | `ratio × 2 × completion_ratio` | CompletionRatio |
| `cached_input_tokens` | `ratio × 2 × cache_ratio` | CacheRatio |
| `cache_write_tokens` | `ratio × 2 × create_cache_ratio` | CreateCacheRatio |
| `audio_input_tokens` | `ratio × 2 × audio_ratio` | AudioRatio |
| `audio_output_tokens` | `ratio × 2 × audio_completion_ratio` | AudioCompletionRatio |
| `per_request` / `image_output_count` | `model_price` | ModelPrice |
| `video_output_second` | **暂不支持**，整行不渲染 | — |

### 3.1 三条兜底规则（避免展示无依据的价格）

1. **绑定不到配置 → 该行不渲染**。宁可少一行，不展示 0 元或错价。
2. **表达式模型（`billing_mode=tiered_expr`）整体不派生**，继续走前端既有的阶梯表达式分支。
3. **没配展示项时**：按 token 计费的模型派生标准「输入 / 输出 / 缓存」三行
   （存量模型零配置即可用）；按次计费的模型**不派生**——它没有真实 token 倍率，
   凭空派生会展示与实际扣费无关的价格。显式编排过展示项的按次模型仍照常渲染。

### 3.2 折扣

按原价 / 现价自动算（`折扣 = 现价/原价×10`，`节省% = (1-现价/原价)×100`），
管理员只填原价。与「分组倍率」是两条独立链路，互不影响。
