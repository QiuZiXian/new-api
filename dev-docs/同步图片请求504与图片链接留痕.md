# 同步图片请求 504 与「图片链接不留痕」处置

## 1. 现象

`POST /v1/images/generations`（Qwen-Image-3.0-pro，2048×2048，京东云 modelservice）：

- 客户端收到 `504 Gateway Time-out`（`nginx/1.27.5`），没有拿到图片；
- 后端日志显示请求**已成功完成并扣费**：
  `use_time_seconds=66`、`预扣费后补扣费：¥0.180000`、`output_image_count=1`；
- 消费日志的 `other` 里只有张数与单价，**没有图片链接**，事后无法追溯生成了什么。

## 2. 根因

### 2.1 504：nginx 默认读超时 60s

nginx 的 `proxy_read_timeout` 默认 **60s**，而该图片模型单次生成实测 **66s**。
上游还没返回，nginx 先断开并返回 504；但后端 goroutine 继续跑到完成，照常结算扣费。

即：**扣费与响应不是同一个生命周期**——网关按超时判失败，后端按完成判成功。
这属于预期行为差异，不是计费 bug，但会导致用户「付了钱没拿到图」。

### 2.2 链接不留痕：响应只写给客户端，没有落到日志

图片链接只存在于 HTTP 响应体里（`data[].url`）。响应被 nginx 丢弃后，
服务端没有任何地方保存它。旧日志里的 `n` / 张数只能证明「生成了几张」，
不能证明「是哪几张」。

## 3. 处置

### 3.1 调大网关超时（部署侧，必须先做）

拓扑见 `API文档部署方案.md`：`nginx-lb`（237 节点，宿主机 `/data/compose/237/nginx/`，
`conf.d` 已挂载到 `/etc/nginx/conf.d`，容器内只读）。

在 `:33000` 的 server / location 块里加：

```nginx
# 同步图片生成实测可达 60-120s，留足余量
proxy_connect_timeout 30s;
proxy_send_timeout    300s;
proxy_read_timeout    300s;
```

如果多个 location 都要，直接放到 `nginx.conf` 的 `http { }` 里全局生效。

生效（不改 compose、不重建容器）：

```bash
docker exec nginx-lb nginx -t
docker exec nginx-lb nginx -s reload
```

验证：同一请求应等待完整时长并返回 200，而不是 60s 处的 504。

> 若前置还有 SLB / CDN / 云厂商网关，它们各自的读超时也要一起调（常见 60s / 120s）。

### 3.2 代码侧：把图片链接写进消费日志

网关超时是部署问题，但「生成了哪几张」必须由服务端自己留证。
已在两处补齐（`consume_log.other.image_urls`）：

| 位置 | 作用 |
|---|---|
| `relay/common/relay_info.go` | `RelayInfo.ImageResultURLs` + `SetImageResultURLs`，最多 8 条、单条截断 2048 字符 |
| `relay/channel/ali/image.go` | 同步/异步图片响应解析后，收集 `data[].url` |
| `relay/channel/openai/relay_image.go` | OpenAI 兼容渠道从响应体 `data[].url` 提取 |
| `service/text_quota.go` | 有链接时写 `other["image_urls"]` |

效果：即使客户端 504，消费日志里仍能看到

```json
"image_urls": ["https://dashscope-....png?Expires=...&Signature=..."]
```

注意：签名 URL 有效期 24 小时，**要长期保存需在该时间内下载转存**。

## 4. 顺带发现的两个待确认项

### 4.1 输入单价与报价不符

本次日志：`image_input_price=0.18`、`image_output_price=0.18`，
而报价是**输入 0.02 / 输出 0.18**。请核对 `ImageCountPrice` 配置中的 `input` 值
（本次是 T2I，`input_image_count=0`，所以没有多扣钱，但文生图以外的场景会多扣）。

### 4.2 请求 4 张，只返回 1 张

客户端传的是 `sequential_image_generation_options.max_images=4`，
但该端点（`/v1/services/aigc/multimodal-generation/generation`）的多图参数是
`parameters.n`（1-6），上游对 `sequential_image_generation*` 不计。
当前自定义 API 路径模式下不自动映射 `parameters`，所以实际按 1 张生成
（日志 `生成数量 1`）。

如需多图，需要决定：把 `n` / `max_images` 映射成 `parameters.n`（会影响所有
自定义路径渠道的请求体），还是继续只支持单图。
