# 真人审核 (Visual Validate) 测试指引

覆盖两段：**上游直连**（cii-group）+ **自身平台**（new-api `/v1/visual-validate/*`）。
配套脚本：`tests/e2e/visual_validate_e2e.py`（标准库实现，无需 pip 安装）。

---

## 0. 前置准备（最容易踩坑的三件事）

1. **渠道**：至少一个 **豆包视频（type 54）** 渠道处于启用状态且 Key 有效。
   服务层用 `service/asset.PickAssetChannel()` 选渠道，只认 type 54 + 启用 + Key 非空。
   渠道 → 高级设置里第 4 个路径 `visual_validate_api_path` **留空即可**（默认 `/api/v1/visual-validate`）。
2. **系统设置 → 服务器地址（Server Address）**：必须填**手机能访问的公网地址**（如 `https://api.example.com`）。
   new-api 用它拼上游 `CallbackURL`。填成 `http://localhost:3000` 的话，手机刷脸完成后浏览器跳不回来，
   回调永远不落库，会话会一直停在 `pending` —— 这是本功能最常见的"看起来没反应"的原因。
   脚本会自动检查并 **WARN**。
3. **API Token**：`sk-xxx`（`TokenAuth`）。回调端点 `/v1/visual-validate/callback` 是公开的，不需要 token。

`tests/e2e/config.json` 里补一段（可选，缺了对应用例会 SKIP）：

```json
"visual_validate": {
  "upstream_base_url": "https://www.cii-group.com/app-api",
  "upstream_key": "你的上游 cii key",
  "upstream_api_path": "/api/v1/visual-validate",
  "project_name": "",
  "downstream_callback_url": "https://webhook.site/xxxx"
}
```

## 1. 上游直连：先证明上游是通的

```bash
# 1) 拉起认证（不扣费，限时免费）
curl -sS -X POST "https://www.cii-group.com/app-api/api/v1/visual-validate/sessions" \
  -H "Authorization: Bearer $UPSTREAM_KEY" -H "Content-Type: application/json" \
  -d '{"CallbackURL":"https://www.example.com/callback"}'

# 期望 200：{"BytedToken":"****...","H5Link":"https://ark.volcengine.com/...","CallbackURL":"https://www.example.com/callback"}

# 2) 拿刚返回的 BytedToken 查结果（还没刷脸 -> 期望 404）
curl -sS -o /tmp/r.txt -w "%{http_code}\n" -X POST \
  "https://www.cii-group.com/app-api/api/v1/visual-validate/results" \
  -H "Authorization: Bearer $UPSTREAM_KEY" -H "Content-Type: application/json" \
  -d '{"BytedToken":"上一步拿到的 token"}'
```

| 用例 | 期望 | 说明 |
|---|---|---|
| sessions 带 CallbackURL | 200，`BytedToken`/`H5Link` 非空 | 401 = key 无效；400 = CallbackURL 为空 |
| results（未刷脸的真实 token） | **404** | 文档：认证记录不存在或已过期 |
| results 空 BytedToken | 400 | 参数校验 |
| results 返回 200 + GroupId | 异常 | 说明该 token 之前已认证过，换新的重测 |

> BytedToken **30 分钟有效、仅能认证一次**。上游测试用掉的 token 不要留着给平台侧继续用。

### 手工等价步骤（想逐步确认时用）

```bash
# 2.1 创建会话
curl -sS -X POST "$BASE/v1/visual-validate/sessions" -H "Authorization: Bearer $SK" \
  -H "Content-Type: application/json" -d '{"callback_url":"https://webhook.site/xxx"}'
# -> {"id":"vv_xxx","byted_token":"...","h5_link":"...","callback_url":"https://<站点地址>/v1/visual-validate/callback?session=vv_xxx&sign=yyy","status":"pending"}

# 2.2 从上面 callback_url 里抠出 session / sign，模拟回调
#    sign 校验失败 -> 400（HTML 错误页）
curl -sS -o /dev/null -w "%{http_code}\n" "$BASE/v1/visual-validate/callback?session=vv_xxx&sign=wrong"

# 2.3 失败分支：resultCode 非 10000 -> 会话变 failed
curl -sS -o /dev/null -w "%{http_code}\n" \
  "$BASE/v1/visual-validate/callback?session=vv_xxx&sign=yyy&resultCode=20001"

# 2.4 成功码但未刷脸 -> 上游 results 404 -> 会话变 expired（验证 404 分支）
curl -sS -o /dev/null -w "%{http_code}\n" \
  "$BASE/v1/visual-validate/callback?session=vv_bbb&sign=yyy&resultCode=10000&bytedToken=<真实token>"

# 2.5 结果接口
curl -sS -X POST "$BASE/v1/visual-validate/results" -H "Authorization: Bearer $SK" -d '{}'                       # 400
curl -sS -X POST "$BASE/v1/visual-validate/results" -H "Authorization: Bearer $SK" -d '{"byted_token":"<真实未认证token>"}'  # 400 且提示"已过期"
curl -sS "$BASE/v1/visual-validate/sessions/vv_xxx" -H "Authorization: Bearer $SK"    # 查状态
```

| 用例 | 期望 |
|---|---|
| `GET /v1/visual-validate/sessions` 不带 token | 401（鉴权生效） |
| `POST /v1/visual-validate/sessions` | 200，5 个字段齐全，`status=pending` |
| `GET /sessions/:id`、`GET /sessions` | 200，能查到刚建的会话 |
| 回调 sign 错误 | **400** |
| 回调 `resultCode≠10000` | 会话 `failed`，`result_code` 原样保存 |
| 回调 `resultCode=10000` 但 token 未认证 | 会话 **`expired`**（上游 404） |
| 重复打同一个回调 URL | 状态不变（幂等，不再打上游） |
| `results` 空 body | 400 |
| `results` 纯透传未认证 token | 400 且 message 含"过期" |
| `results` 传已结束的 `session_id` | 400 "会话已结束" |

> 说明：响应里回显的 `callback_url` 含 sign，看起来像泄漏。但即使有人伪造 `resultCode=10000`，
> new-api 仍要拿 token 去上游换 GroupId，上游返回 404 → 落 `expired`，伪造拿不到任何东西。

## 3. 平台侧：真人刷脸（唯一需要真人的一步）

```bash
python visual_validate_e2e.py --live --image-url "https://xxx/face.jpg"
```

1. 脚本创建会话后打印 **H5Link**，用**手机浏览器**打开（可追加 `&lng=zh` 指定简体中文）。
2. 按页面提示完成人脸认证 → 点"完成" → 浏览器跳转 new-api 回调端点（显示"真人认证成功"HTML 页）。
3. 脚本每 5 秒轮询 `GET /v1/visual-validate/sessions/:id`，直到状态变化或超时（默认 1800s = token 有效期）。
4. 成功判定：`status=succeeded`、`result_code=10000`、`upstream_group_id` 非空（形如 `group-20260331xxxx`）、
   **`local_asset_group_id` 非空**（说明已自动注册为本地素材组）。

时间限制：**30 分钟内必须刷完**，否则只能重新创建会话。

## 5. 数据库核对（出问题时查这里）

表名 `visual_validate_sessions`：

```sql
-- SQLite
sqlite3 data/new-api.db "select public_id,status,result_code,upstream_group_id,local_asset_group_public_id,notify_status,created_at from visual_validate_sessions order by id desc limit 10;"
```

| 字段 | 含义 |
|---|---|
| `status` | `pending` / `succeeded` / `failed` / `expired` |
| `result_code` | 回调里的原始 resultCode（`10000`=通过） |
| `upstream_group_id` | 上游真人素材组 ID |
| `local_asset_group_public_id` | 自动注册的本地素材组公开 ID |
| `notify_status` | 空=无需通知；`notified`=已通知下游；`failed`=通知失败 |
| `sign_token` | 回调防伪造 token（响应里不外露，只有 callback_url 带） |

## 6. 判定速查

| 现象 | 原因 |
|---|---|
| 创建会话返回 502 "上游创建真人认证会话失败" | 渠道未启用 / Key 无效 / `visual_validate_api_path` 填错 |
| 会话一直 `pending` | 回调地址是 localhost（站点地址没配公网）或 H5 认证未完成 |
| 回调后 `expired` | token 过期（>30 分钟）或上游 results 404（没真刷脸） |
| `succeeded` 但 `local_asset_group_id` 为空 | 素材组注册失败，看日志 `register upstream group failed` |
| `notify_status=failed` | 下游 `callback_url` 不可达（best-effort，不影响主流程，可轮询会话状态兜底） |
