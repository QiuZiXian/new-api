## 一、结论摘要（TL;DR）

1. **API Key 无效（阻塞项）**：`sk-1dRPB…skUH` 在本实例所有端点均返回 `401 Invalid token`。
   对照测试显示，它与一个随手编造的假 key 返回**完全一致**的错误，说明该 key 在数据库中不存在、
   已被删除，或属于另一个 new-api 实例。
2. **网关本身是健康的**：服务可达、鉴权中间件工作正常（无 token / 错 token 一律拒绝）、
   路由按源码正确注册、计费参数可正常读取。
3. **无需有效 key 即可确认的两项实质问题**（详见 §4）：
   - `POST /v1/videos/generations`（实测文档里的路径）**未注册**，返回 404；
   - 素材单条操作的正确路径是 `/v1/assets/{id}`，**不是** `/v1/asset-groups/{gid}/assets/{id}`（后者 404）。
4. **计费参数已实测校准**：`QuotaPerUnit=500000`、`USDExchangeRate=5`，
   即 **1 元 = 100,000 quota**。此前配置模板里的 `500 / 7.3` 是错的，已修正。

### 3.3 路由注册矩阵 —— 全量完成

## 六、本次顺带修复的脚本缺陷

测试过程中脚本自身暴露了 3 个问题，已修复，避免换 key 后误报：

1. **`HTTPError` 读 body 抛连接重置**：new-api 返回 401 后可能直接关闭连接，
   `e.read()` 抛 `WinError 10054`，用例被误判成「请求异常」。现在 body 读不到时退化为
   空串，状态码照常采用。
2. **连接重置未重试**：POST 请求撞 RST 时直接崩溃并中断整轮测试。
   现在对 `ConnectionResetError / ConnectionAbortedError / RemoteDisconnected` 重试 2 次。
3. **计费组缺异常兜底**：单个计费用例抛 `ApiError` 会终止整个测试且报告不落盘。
   现已捕获并记为 WARN。
4. **模板默认值错误**：`config.example.json` 的 `quota_per_unit` 原为 `500`（应为 `500000`），已修正。

### 附：判定口径说明

- **PASS**：行为符合预期。
- **FAIL**：行为不符合预期，且已排除环境/鉴权因素。
- **WARN**：需要人工确认（如路由形态与文档不一致、鉴权前提不满足）。
- **SKIP**：前置依赖未通过或配置缺失，主动跳过。
- 服务不可达时，连接类 FAIL 会自动降级为 WARN，避免把网络问题误报成平台缺陷。
