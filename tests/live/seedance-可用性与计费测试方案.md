- 被测环境：`http://www.qsykai.com:33000`（启算云枢）
- 测试范围：仅视频链路 —— 创建 / 查询 / 计费对账 / 分组折扣
- 版本：v1.0（2026-10-29）

## 0. 摸底结论（只读盘点已完成，未产生费用）

| 项 | 实测值 | 来源 |
|---|---|---|
| 计费单位 | quota，`¥ = quota / 500000` | `/api/status`：`quota_per_unit=500000`、`custom_currency_exchange_rate=1`、`quota_display_type=CNY` |
| 分组倍率 | 默认 1.0 / 9.9折扣 0.99 / 9折区 0.9 / 8.5折区 0.85 / 8折区 0.8 / 7.5折区 0.75 | `/api/pricing.group_ratio` |
| 2.0 `model_ratio` | 23 | `/api/pricing` |
| 2.0-fast | 18.5 | 同上 |
| 2.0-mini | 11.5 | 同上 |
| 2.5 | 42.875 | 同上 |
| Seedance 可用分组 | 全部模型 `enable_groups=["默认"]` | 同上 |

**已识别的 4 个高风险点（待实测确认）**

1. **分档倍率可能整条失效**：适配器价格表以 `doubao-seedance-2-0-260128` 这类上游名为键，而对外模型名是 `doubao-seedance-2.0`。若模型映射后查表用的是对外名，则 1080p/4K/含视频输入的档位倍率全部取不到，一律按基准价 46 计费（1080p 会少扣 9.8%）。
2. **mini 含视频倍率与定价表不一致**：代码 `16/28=0.5714`，定价表 `14/23=0.6087`，偏差 6.1%（少扣）。
3. **价格页分档展示错误（已确认，2026-10-29）**：2.0 六个档位在 `/api/pricing` 中全部返回 46；1080p 不含视频标 `origin_price=51 / 9.0折` 但 `price=46`；模型卡标「9.9折」。**结论：后端倍率配置正确，问题在前端模型广场的档位展示映射**（`price_items` 的 `group_key`/`variant` 与价格表未对齐）。记录为 P1 展示缺陷，不阻断计费链路。
4. **折扣分组对 Seedance 不可用**：Seedance 仅启用「默认」组，7.5/8/8.5/9/9.9 折区理论上无法调用，折扣维度可能整块无法验证。

## 1. 测试模型（先定口径，再写用例）

### 1.1 平台扣费公式（按 token 计费的视频）

```
quota = 真实 tokens × model_ratio × 分组倍率 × 档位倍率

真实 tokens =(输入视频秒数 + 输出秒数) × 输出宽 × 输出高 × 24 / 1024
档位倍率   = 该档位单价 / 基准档单价(480p·720p 不含视频)
金额(¥)    = quota / 500000 × 1
```

代入基准档：`1,000,000 tokens × 23 = 23,000,000 quota = ¥46`，与定价表 46 元/百万 token 完全吻合，口径确认。

|---|---|---|---|---|---|---|
| 2.0 | 28 | **46** | 31 | 51 | 16 | 26 |
| 2.0-fast | 22 | 37 | — | — | — | — |
| 2.0-mini | 14 | 23 | — | — | — | — |
| 2.5 | 51.45 | 85.75 | — | — | — | — |

## 2. 用例设计（AAA：准备 → 执行 → 断言）

### A. 可用性（P0/P1）

| ID | 级别 | 准备 | 执行 | 断言 |
|---|---|---|---|---|
| AV-01 | P0 | 有效 Key（默认组） | `POST /v1/video/generations`，C1 参数 | 200/201，返回 `id`，`status ∈ {queued,running}` |
| AV-02 | P0 | 同上 | 每 5s 轮询 `GET /v1/videos/{id}` | ≤10min 进入 `succeeded`；记录端到端耗时 |
| AV-03 | P1 | 任务 succeeded | `GET /v1/videos/{id}/content`（Range 0-1MB） | 200 且 `Content-Type: video/mp4` |
| AV-04 | P2 | — | `POST /v1/videos`（别名） | 可用；`POST /v1/videos/generations`（复数）应 404 |
| AV-05 | P0 | 无 Key / 错误 Key | 同上 | 401，错误体顶层 + `error` 双写，`type=new_api_error` |
| AV-06 | P1 | 有效 Key | 缺 `model`、缺 `prompt`、`resolution=2k` | 400/422；且不产生扣费日志 |
| AV-07 | P1 | 有效 Key | C2（1080p） | 成功，档位倍率 1.1087 生效 |
| AV-08 | P1 | 有效 Key | 触发上游失败（非法 ratio 或超长时长） | `failed`，**不计费或全额退款** |
| AV-09 | P2 | 有效 Key | 2 路并发提交 | 均成功，无 429 外的异常；记录限流行为 |

### B. 计量准确性（P0）

| ID | 执行 | 断言 / 容差 |
|---|---|---|
| M-01 | 提交后立即查日志 | 预扣 quota ≈ 估算 tokens × ratio × 分组；日志含「预估 tokens」 |
| M-02 | 终态后取日志 `quota` 与 `prompt/completion_tokens` | 用真实 tokens 复算 quota，偏差 **≤1%** |
| M-03 | 对比上游真实 tokens 与 1.1 公式值 | 偏差 **≤5%**（估算仅用于预扣，超差要记录） |
| M-04 | 720p 9:16（720×1280）5s | tokens 同为 108,000，计费与 C1 一致（面积相同） |
| M-05 | 含视频输入（2.0 / 720p） | 档位倍率应为 28/46=0.6087，且 tokens 计入输入时长 |
| M-06 | 记录提交前后余额 `/v1/dashboard/billing/subscription` | 余额变动 = 终态 quota/500000（±0.01 元）；预扣差额已退回 |
| M-07 | 日志金额展示 | `quota/500000` 与页面展示一致，四舍五入 ≤0.01 元 |

### C. 折扣准确性（P0）

| ID | 执行 | 断言 / 容差 |
|---|---|---|
| D-01 | 默认组跑 C1 | 倍率 1.0，quota=2,484,000 |
| D-02 | 9折区同参跑 C1 | 比值 0.900 ±0.5% |
| D-03 | 7.5折区同参跑 C1 | 比值 0.750 ±0.5% |
| D-04 | 9折区跑 C2（1080p） | 分组折扣 × 档位倍率连乘，不得重复打折 |
| D-05 | 核对模型卡「9.9折」 | 实扣是否 45.54 元/M；若为 46 则判「展示与计费不一致」 |
| D-06 | 核对价格页 6 个档位 | 展示价 = 实扣价（¥ 差 ≤0.01 或 ≤0.5%） |

**前置校验**：D-02/D-03 需对应分组 Key，且该模型在该分组可用。若 `enable_groups` 仍为 `["默认"]`，直接判「折扣不可用（配置缺陷）」并保留证据，不空跑。

## 3. 抽样策略（本轮 3 组定价 + 1 组折扣）

选样原则：覆盖「基准档 / 跨分辨率档 / 跨模型」三条独立计费路径，且成本可控。

| 组 | 用例 | 覆盖点 | 单次成本 |
|---|---|---|---|
| G1 | C1：2.0 / 720p / 5s | 基准档，锚定 model_ratio=23 | ¥4.97 |
| G2 | C2：2.0 / 1080p / 5s | 跨分辨率档，验证 51/46=1.1087 倍率是否生效 | ¥12.39 |
| G3 | C3：mini / 720p / 5s | 跨模型，验证 ratio=11.5 与 mini 档位表 | ¥2.48 |
| G4 | C1 @9折区（可选） | 分组折扣 0.9 | ¥4.47 |

首轮合计约 **¥24–30**。4K（¥25/条）、2.5、fast 及含视频输入放第二轮回归，避免首轮成本与变量过多。

## 4. 判定与门禁

| 维度 | 门禁 | 不通过处理 |
|---|---|---|
| 可用性 | 抽样 3/3 成功；P0 缺陷 0；端到端 ≤10min | 阻断发版 |
| 计量 | 终态 quota 复算偏差 ≤1%；真实 tokens 与公式偏差 ≤5% | 阻断，出偏差明细 |
| 折扣 | 分组倍率偏差 ≤0.5%；无重复叠加 | 阻断 |
| 展示一致性 | 价格页档位价 = 实扣价（≤0.5%） | 记为 P1（不阻断功能，阻断对外报价） |
| 失败任务 | 不计费或 100% 退款 | P0 |

缺陷分级：P0 计费错误/资金损失/任务不可用；P1 展示与实扣不一致、档位倍率失效；P2 错误码/文案/限流；P3 体验问题。

## 6. 风险与约束

1. **真实扣费**：每条用例都花真钱，首轮限 4 条；失败任务必须核对退款。
2. **凭证**：折扣维度需要 2 个不同分组的 Key；当前 Seedance 仅在「默认」组启用，可能无法执行 D-02/D-03。
3. **上游排队**：`queued` 可能长时间不动，单条超时 10min 记 SKIP，不重复烧钱。
4. **日志延迟**：终态日志可能滞后数秒，对账前等待 5–10s 重试。
5. **估算口径**：`EstimateBilling` 的 tokens 只用于预扣，不能拿它当计量结论，必须以上游真实 usage 为准。
