## 二、P0 问题

### ISS-01 视频生成参数全部未透传上游

**现象**
客户端按对外文档传 `resolution` / `ratio` / `duration` / `seed` / `watermark` / `camera_fixed`，上游实际只收到 `model` + `content`。

**证据（用户提供的上游日志，2026-10-29 19:50）**
```json
upstream POST https://api.zhonghaicn.com/volcengine/api/v3/contents/generations/tasks
body={"content":[{"text":"小猫对着镜头打哈欠…","type":"text"}],"model":"doubao-seedance-2-0-260128"}
```
客户端实际请求体包含：`resolution:720p`、`ratio:16:9`、`duration:5`、`seed:11`、`watermark:true`、`camera_fixed:false`。

**实测佐证**
| 用例 | 请求 | 成片实测 | 结论 |
|---|---|---|---|
| C6 | `duration=10` | 5.088s（mvhd 解析） | 时长未生效 |
| C2 | `resolution=1080p` | 请求体无 resolution，默认 720p | 分辨率未生效 |
| C1 | `ratio=16:9` | 任务详情 `ratio=adaptive` | 比例未生效 |

**根因**
1. `relay/common/relay_info.go:877` `TaskSubmitReq` 只声明 `Size / Duration / Seconds / Images / Metadata`，**没有 `resolution` / `ratio` / `seed` / `watermark` / `camera_fixed` 字段**，JSON 反序列化时直接丢弃。
2. `relay/channel/task/doubao/adaptor.go:603` `convertToRequestPayload` 只读 `req.Seconds`（字符串）构造上游 `duration`，未读 `req.Duration`（整数）。

**影响**
- 1080p / 4K 请求实际生成 720p，用户付费档位与产物不符；
- `duration` 非 5s 的请求全部按默认 5s 生成；
- `watermark=true` 失效（版权/合规风险）；
- 计费按实际（默认档）结算，用户虽未被多扣，但拿到的是错误规格的产物。

**修复建议**
- `TaskSubmitReq` 补齐 `Resolution string`、`Ratio string`、`Seed *int`、`CameraFixed *bool`、`Watermark *bool`，并在 `convertToRequestPayload` 中映射；
- `duration` 取值改为优先 `req.Duration`，回退 `req.Seconds`；
- 补一条单测：请求体带全参 → 上游 payload 字段齐全。

**验收标准**
提交 `1080p / 10s / 9:16 / watermark=true`，上游请求体包含全部字段，成片分辨率为 1080×1920、时长 ≥9.5s。

### ISS-02 渠道 16 的 2.0 请求全量 404

**现象**
2026-10-29 15:19 起，`doubao-seedance-2.0` 的所有请求（含最小参数 720p/5s）返回 `404 fail_to_fetch_task`，响应体为空。

**证据**
- 失败日志 `other.channel_id=16`、`channel_name=字节跳动_7.7折_2.0专用`；
- 同期 `2.0-mini` 走渠道 15 正常，`2.0-fast` 走渠道 15 正常；
- C1 在 12:49 走渠道 1 成功，15:20 重跑走渠道 16 失败；
- 上游 URL 用错误 key 探测返回 **401 `Invalid API key in request`** → **路由存在**，404 是业务层返回；
- 去掉 `/volcengine` 前缀才返回 `404 Route Not Found`，证明当前路径正确。

**根因判断**
渠道 16 所用 key 未被上游授权 `doubao-seedance-2-0-260128`（或该账号未开通该模型），与 URL、参数无关。

**影响**
2.0 全部档位（720p/1080p/4K、含视频/不含视频、分组折扣）无法验证，线上也不可用。

**处理建议**
1. 向提供方确认该 key 的模型权限；
2. 临时禁用渠道 16 或调整路由权重，让 2.0 回到渠道 1；
3. 用同一把 key 执行提供方文档里的 curl，直连复现，区分「key 问题」与「平台拼包问题」。

**验收标准**
2.0 / 720p / 5s 提交成功并进入 `queued → succeeded`。

## 三、P1 问题

### ISS-03 2.0 的 token 为公式值 2 倍

**数据**
| 用例 | 模型 | 分辨率 | 成片时长 | 公式 tokens | 平台 tokens | 偏差 | 实扣 |
|---|---|---|---|---|---|---|---|
| C1 | 2.0 | 720p | 5.088s | 109,901 | **217,392** | **+97.81%** | ¥10.0003 |
| C3 | 2.0-mini | 720p | 5.088s | 109,901 | 108,900 | -0.91% | ¥2.5047 |
| C5 | 2.0-fast | 720p | 5.088s | 109,901 | 108,900 | -0.91% | ¥4.0293 |

**已排除**：分辨率（同为 1280×720）、时长（同为 5.088s）、音轨（三者也都有）、计费链路（同一 adaptor，`quota = tokens × 23` 偏差 0.00%）。

**影响**
2.0 720p 5 秒实付 ¥10.00，按定价表（46 元/百万 token × 108k）应为 ¥4.97，客户成本约 2 倍。

**待办**
拿 217,392 与火山/渠道对账，确认是 2× 帧率、双流（视频+音频）还是渠道加价；若属正常口径，需同步修正定价表的「元/秒」折算与预扣估算公式。

### ISS-04 预扣 tokens 低估约 50%

**数据**
C1 预扣按 108,000 tokens（¥4.968），终态补扣至 ¥10.0003。预扣基数来自 `estimateVideoTokens`（24fps 单流公式），未覆盖 2.0 的实际计量。

**影响**
低余额用户可透支；补扣失败会产生 `unpaid_quota` 欠费（代码已有该字段）。

**建议**
预扣系数按模型分档（2.0 至少 ×2），或在提交前用上游用量接口预检。

### ISS-05 价格页分档展示错误（前端）

**现象**
`/api/pricing` 中 `doubao-seedance-2.0` 六个档位 `price` 全部为 46：1080p 不含视频标 `origin_price=51 / 9.0折` 但 `price=46`；4K 两档也是 46；模型卡另标「9.9折」。

**结论**
后端倍率配置正确（46 / 23 / 18.5 / 42.875 与定价表吻合），问题在**前端模型广场的档位映射**。已由用户确认记录，不阻断计费链路。

**影响**
对外报价与实际档位不符，属报价准确性缺陷。

### ISS-06 档位倍率查表键可能不匹配（待验证）

**代码证据**
`relay/channel/task/doubao/constants.go` 的 `videoPriceTable` 以上游名为键（如 `doubao-seedance-2-0-260128`），而查表传入的是 `info.OriginModelName`（对外名 `doubao-seedance-2.0`）。

**风险**
若 `OriginModelName` 未做映射，`GetVideoInputRatio` 返回 false，档位倍率全部退化为 1.0：1080p 按 46 而非 51 计费（少扣 9.8%），含视频输入不享受 28/31/16 档价。

**当前无法验证**
ISS-01 导致 `resolution` 根本没传给上游，`otherMultiplier` 恒为 1.0000，无法区分「基准档」与「查表失败」。

**验收**
ISS-01 修复后跑 1080p 用例，检查日志 `计算参数` 是否出现 `video_input: 1.11`。

### ISS-05 补充说明（10-30）

- 现象根因不在前端：`PriceItemTable` 只渲染后端下发的 `price`，而 `/api/pricing` 的每行价格由
  `billing_ref` 推导，现有 ref 无法表达「分辨率档 + 是否含视频」，六行都退化成 `model_ratio × 2 = 46`。
- 修复后档位价与实扣口径一致（同一份 `pkg/videopricing` 表）：
  `展示价 = model_ratio × 2 × (档位单价 / 基准单价)`，管理员改 `model_ratio` 时展示与计费同步。
- 存量配置不用改：档位可从「维度」文案识别（`1080p不含视频`、`4K 含视频`、`with video` 等）；
  新配置也可在 `billing_ref` 里显式写 `video_input_tokens:1080p` / `video_input_tokens:4k+video`。
- 待人工确认：档位单价（尤其 4K 26/16）仍以 `pkg/videopricing/videopricing.go` 的注释为准，
  上线前对照火山定价页核对一次。
